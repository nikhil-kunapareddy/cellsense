# Development

## Setting up

**Do not create the virtualenv inside this repository.** See the warning below.

```bash
python3.11 -m venv ~/.venvs/cellsense
source ~/.venvs/cellsense/bin/activate

pip install -e '.[all,dev]'      # editable install, all providers, dev tooling
cp .env.example .env             # then fill in at least one API key
python scripts/make_sample_data.py
```

Verify:

```bash
cellsense --version
cellsense data/sales_2024.csv -q "total revenue by region?"
```

## The `~/Documents` virtualenv trap

If this repository lives under `~/Documents` (or `~/Desktop`) on a Mac with
**Desktop & Documents in iCloud** enabled, do not put a virtualenv inside it.

When the boot volume runs low on space, macOS evicts files in synced folders into
`dataless` placeholders — zero-block stubs that are re-downloaded on first read.
For a `site-packages` tree with tens of thousands of tiny files, that goes wrong in
a specific and very confusing way: **reading an evicted file can block forever in
uninterruptible I/O.** The process sits at 0% CPU and cannot be killed with
`SIGTERM`.

It bites `langchain`/`langgraph` particularly hard, because importing them calls
`importlib.metadata.entry_points()`, which reads *every* `entry_points.txt` in
`site-packages`. One evicted file anywhere in the tree hangs the entire import.

This is not slowness, and it is not a broken install — waiting does not help.

**Diagnosing it**

```bash
# Which file is the hung process stuck on? Look at the last "<n>r" fd.
lsof -p <pid>

# Is that file evicted? "dataless" in the flags confirms it.
stat -f '%N flags=%Sf blocks=%b' <path>

# How widespread is it?
find <dir> -type f -print0 | xargs -0 stat -f '%Sf %N' | grep -c dataless
```

**Fixing it:** recreate the virtualenv outside the synced tree
(`~/.venvs/cellsense` is what the rest of these docs assume). Freeing disk space
stops *new* evictions but does not reliably restore files already stranded by a
provider that has lost the underlying data.

## Everyday commands

```bash
ruff check cellsense tests scripts     # lint
ruff format cellsense tests scripts    # format
mypy                                   # types (config in pyproject.toml)

pytest                                 # everything except live API calls
pytest -m "not live"                   # same, explicit
pytest -m live                         # hits real provider APIs — costs money
pytest --cov --cov-report=term-missing
```

`pytest.ini_options` turns `FutureWarning` into an error, which is deliberate:
pandas 3 deprecations should fail the build rather than accumulate.

## Tests

* `tests/unit/` — no network, no API keys, fast. This is the bulk of the suite.
* `tests/integration/` — the graph end-to-end against a stubbed chat model.
* `tests/integration/test_live_*.py` — marked `live`; real API calls, skipped
  automatically when the relevant key is absent.

Sample data in `data/` is gitignored and regenerated by
`scripts/make_sample_data.py` from a fixed seed. Prefer deriving expected values
with pandas inside the test over hardcoding numbers, so tests survive a
regeneration.

## Adding a provider

1. Create `cellsense/providers/<name>.py` exposing `SPEC: ProviderSpec`.
2. Import the `langchain_*` package **inside** `build()`, converting `ImportError`
   into `MissingDependencyError` — never at module scope.
3. Register it in `cellsense/providers/registry.py`.
4. Add a pip extra in `pyproject.toml`.

Curated model lists are metadata for `/model` and cost display, not a whitelist —
an unrecognised model id must still be usable.

## Adding a tool

1. Create `cellsense/tools/<name>.py` exposing `SPEC: ToolSpec`.
2. Add it to `_MODULES` in `cellsense/tools/registry.py`.
3. Set `side_effect=True` if it writes anything — that routes it through the
   approval gate automatically.

Handlers must not mutate the caller's DataFrames, and must raise `ToolError` with
a message the *model* can act on (list close-matching column names, not just
"KeyError").
